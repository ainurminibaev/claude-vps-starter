# Claude Code на Mac через Codex

Отдельный вариант для Apple Silicon macOS. Штатный `~/.local/bin/claude` остаётся
нетронутым, вместе с обновлениями, историей, памятью, плагинами и авторизацией Claude.
Переключатель меняет только управляемые переменные `env` в пользовательском
`~/.claude/settings.json`. VPS и Telegram-боты от Mac не зависят.

## Установка

Нужны установленный Claude Code, Python 3 и существующий вход в Codex
в `~/.codex/auth.json` (файловое хранилище с ChatGPT OAuth).

Для поиска через shell и context-mode нужен отдельный `rg` в PATH Claude:
`brew install ripgrep`. Встроенный поиск Claude и копия `rg` внутри установки
Codex не обеспечивают доступность команды для subprocess плагина.
Проверка: `command -v rg && rg --version` из окружения Claude/context-mode.
После установки в уже присутствующий `/opt/homebrew/bin` перезапуск сессии
не нужен. Разбор реального инцидента — [аудит инструментов](../docs/10-tooling-audit.md).

```sh
python3 desktop-codex-backend/claude-backend.py install
claude-backend start
# Необязательная живая проверка: Bash, продолжение сессии и Auto Mode.
python3 desktop-codex-backend/smoke.py
claude-backend codex
claude
```

Установщик закрепляет CLIProxyAPI 8.0.47, проверяет SHA256 архива и создаёт
пользовательский LaunchAgent `com.ainur.claude-codex-proxy`. Шлюз слушает только
`127.0.0.1:18418`, использует отдельный локальный ключ, запускается при входе
пользователя и восстанавливается после завершения процесса.
Повторная установка сохраняет OAuth, обновлённый шлюзом.

## Переключение

```sh
claude-backend status       # профиль и доступность шлюза, без секретов
claude-backend codex        # ChatGPT/Codex через локальный шлюз
claude-backend claude       # исходное подключение Claude, шлюз остановлен
```

После переключения нужно перезапустить уже открытые процессы Claude Code.
Используй обычные команды:

```sh
claude -r                  # выбор сохранённой сессии
claude -r SESSION_ID       # конкретная сессия
claude -c                  # последняя сессия текущей папки
```

Оба профиля используют прежнюю папку `~/.claude`; история не конвертируется и
не переносится. Существующие cron/launchd задания, вызывающие этот же Claude и
пользовательские настройки, получат выбранное подключение при следующем запуске.
Явные переменные окружения или настройки проекта могут переопределять профиль;
проверяй `/status`, если конкретный проект ведёт себя иначе.

В режиме Codex команды `/model opus`, `/model sonnet` и `/model haiku` остаются
совместимыми именами интерфейса. Все три ведут на **gpt-6.1-sol, reasoning high**;
это не доступ к моделям Anthropic. Уровень high закреплён на шлюзе, поэтому
ползунок Claude не переключает фактический уровень Codex. Окно автосжатия
ограничено 475000 токенами. Точный подсчёт токенов и некоторые специфичные
возможности Claude могут отличаться при работе через переводчик протокола.

Для возврата подписки: `claude-backend claude`, затем обычный `claude` и при
необходимости `/login` в штатном клиенте. Сохранённый вход Claude не удаляется.
Шлюз использует импортированную авторизацию ChatGPT; `/login` внутри Claude
меняет только вход Claude. Для замены аккаунта ChatGPT сначала переключись на
Claude, сохрани приватную копию `~/.config/claude-backend/auths/codex-local.json`,
удали этот файл, выполни нужный вход `codex login`, затем снова `install` и
`claude-backend codex`. Новый импорт требует файлового `~/.codex/auth.json`.

## Файлы и восстановление

- `~/.local/bin/claude-backend` — независимая команда управления.
- `~/.local/share/claude-backend/cli-proxy-api` — шлюз, отдельно от Claude.
- `~/.config/claude-backend/` — приватные конфигурация, OAuth, локальный ключ,
  состояние профиля и резервные копии настроек; не добавлять в git.
- `~/Library/LaunchAgents/com.ainur.claude-codex-proxy.plist` — служба пользователя.
- `~/Library/Logs/claude-backend/` — журналы шлюза.

При включении сохраняются исходные значения только управляемых переменных,
а также полная приватная резервная копия `settings.json`. Возврат к Claude
восстанавливает исходные переменные, сохраняя изменения прочих настроек,
сделанные за время работы через Codex. `state.json` нужен для восстановления:
не удаляй его при активном профиле Codex. Запускай переключение последовательно.

Если шлюз недоступен: `claude-backend start`, затем `claude-backend status`.
Если порт 18418 занят другой программой, останови её или верни профиль Claude;
не запускай параллельно второй шлюз на этом порту.
Разрешения инструментов, trust диалоги и хуки остаются штатными.
Серверный watchdog на Mac не устанавливается.

Если после обрыва сети идут `503 auth_unavailable` с предыдущей HTML-ошибкой
403, установи актуальную совместимую сборку из
[gateway-patches](../codex-backend/gateway-patches/README.md). Она отличает
HTML-страницу upstream от JSON-ошибок авторизации и допускает повтор через
5 секунд вместо 30 минут. Доступ к сети всё равно должен восстановиться.
Для старой сборки временное восстановление после возвращения сети:
`launchctl kickstart -k gui/$(id -u)/com.ainur.claude-codex-proxy`.
Команда перезапускает шлюз и прерывает его текущие запросы; историю Claude
не меняет. `claude-backend start` только запускает отсутствующую службу,
но не сбрасывает cooldown уже работающей.

Если агент работает, но промежуточные ответы и ответы на вопросы во время
задачи скрыты, см. [исправление commentary](../codex-backend/gateway-patches/README.md).
Это отдельная совместимая сборка шлюза; сам Claude Code остаётся штатным.

Для кодовых запросов включён штатный image `passthrough`: шлюз сохраняет
явно запрошенные инструменты картинок и image endpoints, без автоматического
добавления image tool в каждый запрос. Замеры и ограничения сравнения —
в [диагностике задержек](../docs/09-latency.md).

Первичная проверка Auto Mode использует Medium вместо общего High только
для проверенного нативного stage-one envelope. Основная работа и stage two
остаются High. Неизвестный формат проверки получает прежний High.
Для существующей установки без перезапуска клиента:
`python3 codex-backend/configure_auto_mode.py --apply`.
Откат только этого правила: та же команда с `--revert`.
Замеры и ограничения — в [аудите инструментов](../docs/10-tooling-audit.md).

Опциональная диагностика делает реальные запросы к модели. Сначала
`python3 desktop-codex-backend/auto-mode-capture.py`, затем
`python3 desktop-codex-backend/auto-mode-effort-probe.py`.
Fixture содержит только изолированную синтетическую задачу; policy и отчёты
остаются приватными в `~/.config/claude-backend/auto-mode-audit/`.
`--force-stage-two` у capture добавляет блокировку только безвредной тестовой
записи, чтобы проверить настоящий повторный review; разрешающий ответ не подделывается.

Проверки профиля без запросов к модели:
`python3 -m unittest discover -s tests -p 'test_desktop_backend.py'`.
Живой `smoke.py` использует временные настройки и историю, проверяет реальный
Bash-вызов, `-r` и отдельную проверку Auto Mode без разрешающего правила Bash,
затем удаляет только свою тестовую папку.

Auto Mode использует отдельный `claude-sonnet-5`, даже когда основная модель
и Sonnet-алиас настроены на версию 5.5. Этот ID также направляется на Codex;
классификатор выполняет настоящий запрос к модели, без подстановки разрешений.
Ошибка `unknown provider for model claude-sonnet-5` в журнале означает, что
конфигурацию шлюза нужно обновить повторным `install`. Нативные read-only
инструменты и MCP-инструменты context-mode проходят разные проверки:
`ctx_execute` и `ctx_batch_execute` могут выполнять код и требуют классификатора.
Строка `SendFeedback(...)` в интерфейсе — действие клиента, а не ошибка хука.
