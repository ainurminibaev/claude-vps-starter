# Видимые промежуточные ответы Codex

В CLIProxyAPI 8.0.47 публичные сообщения Codex с `phase: commentary` переводятся
в Claude-блоки `thinking` с подписью `cpa:commentary:v1`. Claude Code скрывает
их в обычном интерфейсе. Агент продолжает работать и отвечать на вопросы,
но ответы во время длинной задачи выглядят как молчание.

Здесь хранится небольшой opt-in patch поверх upstream
`90c447d3a8727d115aa7552ec93ce023736ed492` (`v8.0.47`). При
`CPA_VISIBLE_CODEX_COMMENTARY=1` шлюз сохраняет исходный блок с маркером фазы
и показывает публичное сообщение также обычным текстом. При обратной отправке
истории соседняя видимая копия удаляется: в Codex уходит один исходный
`commentary`, без дублирования контекста. Настоящие reasoning-блоки этим
механизмом не выводятся как публичный текст.

Правка не создаёт дополнительных генераций и не меняет reasoning effort,
разрешения инструментов, CLI Claude, плагины, память или UUID сессий.
В локальной истории остаются обе формы публичного сообщения — скрытый маркер
для точного replay и видимый текст для человека.

## Воспроизведение сборки

Нужны git и Go 1.26.10 или совместимый toolchain. Скрипт проверяет точный
upstream commit, применяет patch, запускает весь пакет тестов переводчика и
собирает отдельный бинарник. Скомпилированные файлы в git не добавляются.

```sh
bash codex-backend/gateway-patches/build.sh darwin arm64 /tmp/cpa-mac
bash codex-backend/gateway-patches/build.sh linux amd64 /tmp/cpa-linux
```

При необходимости укажи абсолютный путь к компилятору через `GO_BIN`.
Версия результата: `8.0.47-itab.1`.

## Проверка и установка

Живая проверка запускает кандидата на отдельном свободном loopback-порту,
использует отдельную временную историю Claude и проверяет видимый progress,
реальный Bash-вызов и `-r`. Она делает обычные запросы к Codex.
Для JSON-конфига дополнительных Python-пакетов нет; для VPS YAML нужен PyYAML.

```sh
python3 codex-backend/gateway-patches/smoke.py \
  --binary /tmp/cpa-mac --config ~/.config/claude-backend/config.yaml
shasum -a 256 /tmp/cpa-mac
python3 codex-backend/gateway-patches/install.py /tmp/cpa-mac --sha256 ACTUAL_SHA256
```

На VPS передай Linux-бинарник и используй серверный config, с
`--claude /usr/bin/claude` для smoke-теста. Установщик сам выбирает пути
Mac или VPS. Перед заменой он ждёт завершения запросов, известных из логов
session-affinity; это вспомогательная проверка, не полноценный server-side drain.
Если шлюз постоянно занят, установка завершается без замены бинарника.

Установщик не приостанавливает клиентские процессы: на Mac это меняет job
control терминала, и одного SIGCONT недостаточно для возврата CLI на передний
план. Если сессия была приостановлена вручную, в её терминале выполни
`fg %claude`. Для обновления постоянно загруженного шлюза выбери паузу между
задачами и повтори установку.

Установщик сохраняет `cli-proxy-api.before-commentary`, включает флаг только
в службе шлюза и перезапускает только её. Он проверяет доступность модели и
откатывает бинарник и конфигурацию запуска при ошибке. Mac LaunchAgent может
кратковременно отклонять повторную регистрацию после unload: установщик
повторяет bootstrap. Нативные клиенты после обновления не перезапускаются.

При последующей установке Mac можно явно передать бинарник:
`claude-backend install --proxy-binary /tmp/cpa-mac`. На Linux:
`CODEX_PROXY_BINARY=/tmp/cpa-linux bash codex-backend/install.sh root ...`.
Обычный Linux installer без этой переменной устанавливает stock release и
заменит исправленную сборку; для сохранения исправления передавай свой бинарник.

## Возврат и обновления

Профиль `claude` обходит шлюз и использует штатную подписку. Чтобы вернуть
stock-шлюз, замени исполняемый файл резервной копией и перезапусти его службу
в паузе между запросами. Stock-сборка игнорирует флаг видимого commentary.
Старые маркеры `cpa:commentary:v1` остаются совместимыми с upstream.

Для обновления CLIProxyAPI сначала проверь upstream: если там появился свой
режим видимого commentary, предпочти его. Этот patch привязан к 8.0.47;
не применяй его вслепую к другой версии.

Для больших запросов в конфигурациях включено поддерживаемое upstream сжатие
`upstream.codex.upstream-request-compression: true` (zstd). Оно сокращает
передаваемые байты, сохраняя текст, токены и effort. При отказе upstream
400/415 реализация повторяет запрос без сжатия. Это не обещание ускорения
самой генерации: High, объём контекста, отдельные проверки Auto Mode и
состояние сети продолжают влиять на задержку.
