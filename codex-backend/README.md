# Codex backend

Этот каталог содержит воспроизводимую установку отдельного транспорта модели.
Основная инструкция: [переключение и возврат](../docs/08-codex-backend.md).

| Файл | Назначение |
|---|---|
| `install.sh` | CLIProxyAPI 8.0.47, Linux x86_64, SHA256 опубликованного релиза; установка службы и обвязки |
| `config.example.yaml` | Loopback, клиентская авторизация, High, SSE keepalive и повторы |
| `codex-model-proxy.service` | Systemd-служба с автозапуском и перезапуском при сбое |
| `prepare.py` | Импорт готового Codex OAuth и выдача отдельных локальных ключей пользователям |
| `configure_cron.py` | Переключение только `BASH_ENV` в выбранном crontab (`--user`, по умолчанию root) с резервной копией |

Запуск из корня репозитория на сервере:

Нужны Linux x86_64, Python 3, curl, tar, systemd и готовая авторизация Codex у
root в `/root/.codex/auth.json`. Для отдельного входа сервера можно использовать
`codex login --device-auth`. Установщик не запускает браузерный вход сам.

```bash
sudo -H bash codex-backend/install.sh root ilshat wife
```

Аргументы — пользователи, которым выдаётся доступ. Существующие клиенты и
обновлённые OAuth-токены сохраняются при повторном запуске. Установщик не
выбирает модель для ботов и не перезапускает их. Список пользователей сервера
хранится в реестре `claude-tg-instances/registry.md`, рабочий список сессий — в
`scripts/claude-tg-watchdog.sh`. Включать режим и выполнять перезапуски следует
по одному, по инструкции выше.

Настоящие ключи, `config.yaml`, клиентские env-файлы и OAuth находятся за
пределами репозитория в закрытых каталогах пользователей. Бинарник скачивается
из [релиза CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI/releases/tag/v8.0.47)
и в git не добавляется. В репозитории остаются установщик, шаблон, служба,
скрипты запуска, документация и тесты.
