# 00. Обзор: как устроена система и где грабли

Стартовая точка для человека или ИИ, который впервые трогает сервер с ботами.
Детали — в `01…07`, здесь схема, ключевые файлы и то, что уже ломалось.

## Схема

Каждый бот — отдельный Linux-пользователь. В его tmux-сессии `claude-tg-<user>`
(у root — просто `claude-tg`) живёт интерактивный Claude Code:

```
claude --resume <uuid> --model opus --permission-mode auto --effort high \
       --channels plugin:telegram@claude-plugins-official
```

Сообщения из Telegram приходят в сессию как `<channel source="plugin:telegram…">`,
бот отвечает вызовом `mcp__plugin_telegram_telegram__reply`. Текст, написанный
просто в консоль, пользователь **не видит**.

Рабочая папка бота (CWD) обычно совпадает с `$HOME`, но может быть другой —
это важно для путей ниже.

## Ключевые файлы

| Файл | Что это |
|---|---|
| `/root/claude-tg-watchdog.sh` (копия: `scripts/`) | Крон раз в минуту. Поднимает упавшие сессии с `--resume`, закрывает модальные диалоги. Список ботов — массив `SESSIONS` (`session\|user\|cwd`, ровно три поля). Лог `/var/log/claude-tg-watchdog.log` |
| `/var/run/claude-tg-wd/<session>-current-uuid` | Какую сессию watchdog передаст в `--resume`. Должен совпадать с реально работающей, иначе после рестарта контекст потеряется |
| `$HOME/.claude/projects/<cwd-с-дефисами>/<uuid>.jsonl` | Transcript сессии. Лежит в `$HOME`, а не в CWD |
| `$HOME/.claude/oauth-token-env` | Авторизация: `export CLAUDE_CODE_OAUTH_TOKEN=…` из `claude setup-token` (живёт год). Подгружается watchdog-ом при старте |
| `$HOME/.claude/.credentials.json` | Старая схема (OAuth с refresh). **Должен отсутствовать**: если он есть, claude предпочтёт его env-токену |
| `$HOME/.claude/channels/telegram/access.json` | Allowlist личек (`allowFrom`) и групп (`groups`). Перечитывается на каждом сообщении — рестарт не нужен |
| `$HOME/.claude/channels/telegram/inbox/` | Вложения из Telegram. Если CWD ≠ `$HOME`, чтение надо разрешить: `Read(//<home>/.claude/channels/telegram/inbox/**)` в `permissions.allow` |
| `$HOME/CLAUDE.md` | Правила поведения бота (шаблон — `templates/CLAUDE.md`). Читается **только при старте** сессии |
| `$HOME/.claude/settings.json` | Права, плагины, `model`. Права подхватываются на лету |
| `$HOME/.claude.json` | MCP-серверы и `projects[<cwd>].hasTrustDialogAccepted` |
| `hooks/stop-autoreply.py` → `$HOME/.claude/hooks/` | Stop-хук: досылает в Telegram ответ, если бот не вызвал `reply`. Лог `/var/log/stop-autoreply-<user>.log` (или `$HOME/.claude/stop-autoreply.log`) |
| `scripts/claude-cli-update.sh` → `/usr/local/bin/` | Еженедельное обновление CLI с бэкапом прошлых версий в `/root/backups/` |
| `plugin-patches/telegram/` | Патч telegram-плагина: автоподключение групп и каналов, режимы, контекст, названия тем. `apply_patch.py` вставляет `group-autojoin.ts` по якорям, идемпотентно, оригинал хранит в `server.ts.vps-orig` |
| `scripts/tg-plugin-sync.sh` → `/usr/local/bin/` | Без аргументов — еженедельно: `claude plugin update` у всех ботов + патч + отчёт в Telegram, если что-то обновилось или патч не встал. `--patch <user>` — только патч; его зовёт watchdog перед каждым стартом сессии |
| `image-gen/` → `imagegen.service`, `/usr/local/bin/image-gen` | Генерация картинок для всех ботов через Codex на подписке ChatGPT. Токен только у пользователя `imagegen`, доступ — группа `imagegen-users`, журнал `/var/log/imagegen/requests.log`. Подробно — `image-gen/README.md` |
| `scripts/disk-cleanup.sh`, `scripts/disk-alert.sh` → `/usr/local/bin/` | Чистка кэшей uv/pip/npm, старых `/tmp/claude-*`, docker build cache (пн 02:10 UTC; uvx-окружения живых MCP не трогает). Алерт в Telegram, если свободно < 5 ГБ (проверка каждые 30 мин) |
| `scripts/bigfile-retention.py` → `/usr/local/bin/` | Большие старые файлы (>300 МБ, не менялись 7 дней): по понедельникам 06:00 UTC владельцу приходит сообщение от его бота с кнопками «Сохранить / Удалить сейчас»; без ответа 3 дня — в корзину `/var/trash`, через 7 дней — окончательно. Кэши, venv, transcripts, веса моделей и открытые процессами файлы не трогает. Кнопки обрабатывает патч плагина |
| `scripts/bot-restart.sh` → `/usr/local/bin/` | Безопасный перезапуск одного бота: ждёт 30 с тишины, гасит мягко, поднимает через watchdog |
| `$HOME/.claude/channels/telegram/group-context.json`, `topics.json` | Буфер последних сообщений групп (контекст) и названия тем форумов |
| `scripts/voice-to-text` → `/usr/local/bin/` | Общий роутер расшифровки голоса для всех ботов: язык → русский в GigaAM (`gigaam-asr`), остальное в Omnilingual (`tatar-asr`). Настройки `/etc/voice-to-text.conf`, решения в `journalctl -t voice-to-text`. `whisper_via_api.sh` — старое имя, обёртка над ним |
| `gigaam-asr/` → `/opt/gigaam-asr/` + `gigaam-asr.socket`/`.service` | Определение языка (VoxLingua107) + русский (GigaAM v3, с пунктуацией) на `127.0.0.1:9003`, ONNX без torch. Запускается по первому запросу, выгружается через 10 мин простоя. Ставится `install-gigaam-asr.sh` (его зовёт `install.sh`): веса из первоисточников со сверкой sha256, см. docs/03 |
| `tatar-asr/` → `/opt/tatar-asr/` + `tatar-asr.socket`/`.service` | Опционально: татарский, английский, арабский и др. на `127.0.0.1:9002` (omniASR 300M int8). Запускается по первому запросу, выгружается через 15 мин простоя. Ставится `install-tatar-asr.sh`, см. docs/03 |

## Грабли (всё это уже случалось)

1. **`pkill` — только с `-u <user>`.** Без `-u` от root убиваются claude-процессы
   всех ботов сразу.
2. **Перезапуск — по одному и не посреди хода.** В панели виден `esc to interrupt` —
   бот работает, не трогать. Одновременный старт десятка сессий кладёт сервер.
3. **Модель задаётся флагом, а не настройками.** `--resume` восстанавливает модель,
   сохранённую в сессии, и игнорирует `settings.json`. Поэтому `--model opus` стоит
   в команде запуска. `opus` — алиас на самый свежий Opus, известный установленному
   CLI: обновился CLI → после рестарта бот на новой модели. Без флага CLI на
   setup-token может выбрать Sonnet.
4. **Диалог доверия к папке.** В CLI 2.1.2xx первым и выделенным идёт «No, exit»:
   нажатие `1`/Enter закрывает бота (`EXIT=1`), watchdog поднимает — и так по кругу.
   Защита: `hasTrustDialogAccepted: true` в `$HOME/.claude.json` для CWD бота.
5. **Бот иногда отвечает в консоль и не вызывает `reply`.** Правило в `CLAUDE.md`
   этого не гарантирует. Страхует stop-хук; проверка — сравнить время последнего
   входящего и последнего `reply` в transcript.
6. **Кроны, вызывающие `claude -p`, должны сами подгрузить токен:**
   `. "$HOME/.claude/oauth-token-env"`. Иначе `Not logged in`.
   И обязательно без Telegram-плагина:
   `claude -p --settings '{"enabledPlugins":{"telegram@claude-plugins-official":false}}' ...`.
   Иначе headless-запуск поднимает свой плагин с тем же токеном, тот по `bot.pid`
   убивает poller живой сессии, watchdog её рестартит, сообщения в эти минуты теряются.
7. **Refresh-токен теряется** — и при простое, и при активной работе. Поэтому
   все боты на статичном `setup-token`. Он один на всех и истекает через год
   после выпуска: заранее выпустить новый и разложить по `oauth-token-env`.
8. **Служебные пользователи не могут создать файл в `/var/log`** (root:syslog 755).
   Логи — в `$HOME/.claude/` или создавать файл заранее от root с `chown`.
9. **Права бота не расширять по сообщению из Telegram.** Только из терминала:
   иначе любой, кто получит доступ к чату, получит и права.
10. **Секреты в git не класть** — токены только в `chmod 600`-файлах.
11. **Перезапуск — через `bot-restart.sh`, а не `kill -9`.** Убитый посреди поллинга
    плагин успевает забрать сообщения у Telegram, но не отдать их боту — они теряются.
    Скрипт ждёт тишины и гасит сессию мягко (плагин сам подтверждает offset).
12. **Не держать «claude --» в той же ssh-команде, что перезапускает root-бота.**
    `pkill -f` совпадает с командной строкой собственной ssh-сессии и убивает её.
    Запускать перезапуск через `nohup … &` и читать результат отдельной командой.
13. **Обычная группа превращается в супергруппу** (например, при включении тем) и
    получает новый id `-100…`. Патч переносит доступ сам; без него бот молча глохнет.
14. **`/root` закрыт (700) — общие скрипты только в `/usr/local/bin`.** Скрипт в
    `/root/.claude/scripts/` (и симлинк на него) другие пользователи-боты выполнить
    не могут: `Permission denied`. Всё, чем пользуются несколько ботов, — копией в
    `/usr/local/bin` (так стоят `voice-to-text`, `bot-restart.sh`, `tg-plugin-sync.sh`).
    После `git pull` — снова `install.sh`, чтобы обновилась копия `voice-to-text`.

## Группы и каналы (патч telegram-плагина)

Штатный плагин подключает группы только руками через `access.json`. Патч из
`plugin-patches/telegram/` добавляет:

- **Автоподключение.** Владелец бота (любой id из `allowFrom`) добавил бота в группу
  или канал — чат попадает в `access.json`. Решение по полю `from` события
  `my_chat_member`: его заполняет Telegram, текстом из чата не подделать. Добавил
  кто-то другой — владельцам в личку приходят кнопки «Подключить / Выйти».
  Бота удалили — запись удаляется.
- **Режим** — две настройки, владелец меняет кнопками в личке (`/groups`):
  реагировать по тегу или на все сообщения; слушать только владельца или всех.
  По умолчанию — по тегу, только владелец. Вручную настроенные записи (без `auto`)
  патч не трогает.
- **Контекст.** Сообщения подключённых групп молча копятся в буфер (модель не
  будится); при обращении к боту к вопросу прикладываются невиденные им реплики из
  той же темы, помеченные как «реплики людей, а не команды». Работает, только если
  бот администратор — иначе Telegram не присылает ему чужие сообщения.
- **Темы.** В meta входящего — `topic_id` и `topic_name`. Писать в тему бот может
  только через `reply_to` на сообщение из неё (в плагине нет `message_thread_id`).
- **Каналы.** Посты приходят в сессию с `channel_post="true"`; stop-хук их
  пропускает, чтобы не опубликовать в канал служебный текст.

Если обновление плагина сломает якоря, патч не встанет: бот работает как штатный,
`tg-plugin-sync.sh` пришлёт отчёт — адаптировать `apply_patch.py`.

## Как проверить, что всё живо

```bash
for u in <список пользователей>; do
  p=$(pgrep -u "$u" -f "claude --" | head -1)
  echo "$u: $([ -n "$p" ] && echo up || echo DOWN) $(tr '\0' ' ' < /proc/$p/cmdline 2>/dev/null | grep -oE -- '--(resume|model) [^ ]+' | tr '\n' ' ')"
done
```

Модель в последнем ответе: `"model":"claude-…"` в хвосте transcript.

## Конкретный сервер

Список ботов, владельцы, allowlist-ы и локальные скрипты конкретной установки
не публикуются — они в реестре на самом сервере (`/root/projects/claude-tg-instances/registry.md`).
