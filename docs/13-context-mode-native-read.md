# Штатное чтение файлов при использовании context-mode

Локально и на VPS 2026-11-03 исправлены только три источника подсказок установленного
Claude-плагина context-mode: `hooks/routing-block.mjs`,
`skills/context-mode/SKILL.md`, `configs/claude-code/CLAUDE.md`.
Хуки разрешений, выполнение инструментов, шлюз, модель и проектные правила
не менялись. Отдельный плагин приложения Codex этим исправлением не обновлялся.

На VPS исправлены активные установки root и marusya (1.0.169), wife, rafka,
bulatov, alfiya-mama-rafka и rishat-rafka-papa (1.0.103). У khazrat, niyaz,
diana и ilshat context-mode не установлен: добавлять его ради этой правки
не требуется. Перед установкой проверены копии всех семи установок; после
установки проверен импорт ROUTING_BLOCK/READ_GUIDANCE и наличие нового правила.
Все семь ботов последовательно перезапущены через штатный bot-restart.sh;
каждый возобновил прежний UUID сессии. Результаты на сервере:
`/root/native-read-rollout-20261103.log`.

Причина: прежние подсказки направляли анализ файлов из Read в MCP. В тестах
Astra/Sol, включая субагентов, чтение рабочего файла через Python в MCP
не вызывало нативную загрузку вложенного CLAUDE.md. Read вызывал её.
Явное чтение самого CLAUDE.md через MCP всё же доставляет его текст модели.
Отсутствие InstructionsLoaded не доказывает отсутствия текста: при прямом
Read инструкции событие также может не повторяться.

Новая маршрутизация оставляет чтение проектных файлов, инструкций и связанных
процессов штатному Read; большие данные можно фильтровать/агрегировать через
context-mode после получения применимых инструкций. Это рекомендация модели,
а не технический запрет MCP. Полное соблюдение инструкций не гарантируется.

## Проверки

Изолированные процессы Claude 2.1.316, Astra medium, искусственный проект
с вложенным CLAUDE.md, отдельным PROCESS.md, JSON-шаблоном и проверкой точных
полей результата. Все восемь запусков успешно создали ожидаемый результат:

- Текущий плагин: два запуска, инструкции прочитаны через MCP; штатная
  подгрузка вложенных правил зарегистрирована при Write.
- Исправленный: два запуска, инструкции и процесс прочитаны через Read.
- Без плагина: два запуска, инструкции и процесс прочитаны через Read.
- Субагенты: по одному запуску исправленного варианта и без плагина;
  оба прочитали инструкции через Read и выполнили задачу.

Доказано изменение выбора инструментов, а не повышение качества результата:
исходный плагин также прошёл эту небольшую задачу. Реальный медиаплан Hongqi
не изменялся и заново этим тестом не создавался.

67 тестов маршрутизации прошли, 9 Security-тестов исключены из отдельного
целевого прогона. В полном исходном наборе уже падали 5 Security-тестов;
в кандидате воспроизводились те же 5 плюс устаревшая проверка, требовавшая
перенаправления Read в MCP. Последняя заменена проверкой нового поведения
в изолированной копии тестов. Полный набор зелёным не объявляется.

Результаты: `context-mode-native-read-results-20261103.jsonl`.
Эксперимент: `tests/manual_context_mode_read.py` (запускать до установки
патча; после установки путь current уже указывает на исправленный плагин).

## Установка и откат

Скрипт `desktop-codex-backend/context-mode-native-read.py` рассчитан на
проверенные установленные копии 1.0.25, 1.0.103 и 1.0.169. Поддерживает как
статические экспорты, так и фабрики подсказок. Для другой версии сначала
сверить исходник и повторить тесты, не применять вслепую.

Резервная копия трёх файлов:
`~/.config/claude-backend/backups/context-mode-native-read-20261103/`.
На VPS: `/root/context-mode-native-read-backups-20261103/<user>/`.
Для отката вернуть эти файлы на соответствующие места в каталоге плагина.
Обновление плагина может перезаписать локальную правку. Открытые сессии
возобновить через `claude -r`, чтобы обновились стартовые инструкции.
